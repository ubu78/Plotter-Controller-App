# Plotter Controller (Rust)

Десктопное приложение для управления перовым плоттером на базе **GRBL 1.1** (например, [Scalable-Pen-Plotter](https://github.com/ubu78/Scalable-Pen-Plotter)) по последовательному порту. Бэкенд на **Rust** (tao + wry/WebKitGTK, serialport), интерфейс React встроен в бинарник — приложение открывается в собственном окне, **без браузера, без HTTP-сервера и открытых портов**.

## Возможности

- 🔌 Подключение к GRBL через COM/USB-порт: статус (Idle/Run/Hold/Alarm), `$`-параметры с пресетом для плоттера, soft-reset, feed hold, крупные кнопки **$X** (разблокировка) и **$H** (homing), список портов с автоопределением Arduino/CH340
- ⚡ Быстрая отрисовка «как в программе №1»: потоковая передача G-кода окном (character-counting, окно 120 байт в 128-байтном RX-буфере платы) — планировщик GRBL видит 10–20 блоков вперёд, без торможения на стыках сегментов и без USB-round-trip на каждую строку
- 🖼 Импорт SVG → G-code с автомасштабированием под лист (**макс. формат — A4**) и настоящими дугами **G2/G3** (адаптивное разбиение кривых 0.02 мм + подгонка дуг)
- ✍️ **Текст / Markdown → G-code**: вставляете текст или .md — программа сама раскладывает строки и генерирует G-code; шрифты **Google Fonts** и **все шрифты, установленные в системе** (имя из самого файла, чтение с диска, без интернета) + **начертание** (Обычный/Жирный/Курсив/Жирный курсив) и живой предпросмотр реальными контурами; настройка размера и межстрочного интервала
- 🖋 Четыре стиля букв: «Ручка» (одна линия по штриху, без обводки контура) / «В одну линию» / «Залитые» / «Штриховка» (угол 0–180°)
- 📄 **Документ → G-code**: загрузка PDF / DOCX / TXT / MD — извлечение текста или однолинейная растеризация страницы в один клик
- 🪞 **Инвертировать Y**: если печать выходит зеркальной по вертикали (ось Y станка направлена вверх от точки старта — стандартное CNC-направление), включите галочку в карточке SVG — рисунок переворачивается на месте, габариты и положение на листе не меняются; дуги корректно меняют направление G2↔G3; настройка запоминается
- 🧭 **Начало Y станка**: три режима отсчёта Y относительно листа — «Верхний край» (Y = расстояние от верхнего края, как в предпросмотре — для протяжки листа вперёд), «Нижний край» (стандарт ЧПУ: ноль у нижнего края листа, Y вверх — рисунок ложится у верхнего края настоящего листа) и «Реверс» (Y = −Y для станков, у которых при Y+ лист уходит назад — координаты становятся отрицательными и лист подаётся в правильную сторону); высота листа берётся из «Бумага», дуги G2↔G3, предпросмотр показывает физическое положение на листе
- 🗺 Визуальный предпросмотр траектории пера, ручное управление (jog), рабочие системы координат **G54–G59**, нули осей, мм/дюйм
- 🖊 Перо: серво через выход шпинделя (`M3/M5`) или ось Z; пресеты одной кнопкой — «№1: ↑ M5 · ↓ M3 S30» (перо вверх **без угла, на градус смотреть не нужно**) и «↑ M3 S45 · ↓ M5»; ползунок положения сервы и быстрый тест пера
- ▶️ Управление печатью: Печатать / Пауза / Продолжить / **Стоп печать** (0x18), подача `F` один раз в начале файла, live-override **F− / F% / F+** с индикатором
- 📋 Блок «Готовый G-код»: **откройте файл** (.gcode/.ngc/.nc/.tap/.txt — вставляется сразу и в поле, и в панель G-код) или вставьте программу из буфера (Ctrl+V прямо в поле — надёжно в WebKitGTK), «Применить» — для текста из поля; редактор G-кода: правка, вставка, копирование, сохранение в файл
- 🛠 Настройки GRBL ($0–$132) с пресетом для плоттера
- 🌐 Локализация ru / en / et
- 🧪 Встроенный самотест: приложение проверяет себя в настоящем окне на мок-плате GRBL — без реального железа

## Быстрый старт (из исходников)

Требуется Rust ≥ 1.85 и Node.js ≥ 18. Системные пакеты (Debian/Ubuntu): `libwebkit2gtk-4.1-dev`, `libgtk-3-dev` (сборка) и `libwebkit2gtk-4.1-0` (запуск).

```bash
cd ui && npm install && npm run build && cd ..   # интерфейс -> ui/dist (встраивается при компиляции)
cargo build --release                            # окно без localhost
./target/release/plotter-controller
```

### Доступ к последовательному порту (Linux)

```bash
sudo usermod -aG dialout $USER   # затем перелогиниться
```

## Сборка AppImage (Linux x86_64)

```bash
bash appimage/build-appimage.sh
```

Скрипт собирает фронтенд, компилирует release-бинарник и упаковывает всё в один файл
`release/Plotter-Controller-<версия>-x86_64.AppImage`. Node.js в рантайме не нужен. Запуск:

```bash
./release/Plotter-Controller-0.5.18-x86_64.AppImage
# если FUSE недоступен:
./release/Plotter-Controller-0.5.18-x86_64.AppImage --appimage-extract-and-run
```

## Самотест (без реальной платы)

Приложение умеет проверять само себя в настоящем окне: конвертеры, сохранение файла, подключение, события.

```bash
python3 scripts/pty_mock.py &          # имитация платы GRBL на паре pty (печатает имя порта, напр. /dev/pts/5)
PLOTTER_SELFTEST=1 PLOTTER_SELFTEST_PORT=/dev/pts/5 ./target/release/plotter-controller
# на машине без экрана: xvfb-run ./target/release/plotter-controller
# печатает: SELFTEST {"status":true,"svg":true,...} и завершается
```

## Структура

```
plotter-controller-rs/
├── src/                # бэкенд Rust
│   ├── main.rs         # окно (tao + wry/WebKitGTK), схема plotter://app/, IPC, самотест
│   ├── api.rs          # единый диспетчер запросов UI ↔ Rust
│   ├── grbl.rs         # связь с GRBL: потоковое окно (character-counting), ok-подтверждения, опрос «?», шина событий

│   ├── svg.rs          # SVG → полилинии, подгонка дуг G2/G3
│   ├── text.rs         # текст/Markdown → G-code, Google Fonts (кэш ~/.cache/plotter-controller/fonts)
│   ├── skeleton.rs     # однолинейные буквы: растр → Zhang–Suen → трассировка → RDP; PDF-страницы
│   ├── doc.rs          # DOCX (zip+roxmltree), TXT/MD (utf-8/cp1251), PDF-текст (pdf-extract)
│   └── pdf.rs          # PDF-страница как рисунок: hayro → растр → однолинейные штрихи
├── ui/src/             # React 18 + Vite (встраивается в бинарник через rust-embed)
│   ├── components/     # ConnectionPanel, ManualPanel, PenPanel, SourcePanel, PastePanel,
│   │                   # Preview, GcodePanel, SettingsPanel, ConsolePanel
│   ├── api.js          # единственная точка транспорта UI ↔ Rust
│   └── i18n.js         # ru / en / et
├── scripts/
│   └── pty_mock.py     # мок платы GRBL для самотеста
└── appimage/           # сборка AppImage (AppRun, .desktop, иконки, скрипт)
```

## Ограничения оборудования

- Максимальный размер бумаги — **A4** (210 × 297 мм); всё автоматически вписывается в область печати плоттера.
- Поднимаемая/опускаемая перьевая ось управляется через выход шпинделя `M3/M5` (серво SG90; при `$30=180` значение S — градусы 0–180) либо через ось Z — режим выбирается в «Настройках пера».
- Начало листа — левый верхний угол, X вправо, Y вниз (протяжка бумаги); ноль по кнопке «0» — `G10 L20 P1 X0 Y0`. Если станок считает Y иначе — селект «Начало Y» в карточке SVG («Нижний край» — стандарт ЧПУ, «Реверс» — лист подаётся назад при Y+).

## История версий

Кратко, полная история — в git-логе и описаниях коммитов:

- **0.5.18** — начало Y станка: новая проблема — предпросмотр и SVG показывают рисунок у верхнего края листа, а при печати станок прокручивает лист и рисует не там; «Инвертировать Y» не помогает, потому что оно зеркалит рисунок вокруг его собственных габаритов (диапазон Y не меняется) и не может перенести рисунок на другой край листа. В карточке SVG появился селект «Начало Y»: «Верхний край» (как раньше — Y = расстояние от верхнего края, подача листа вперёд), «Нижний край» (стандарт ЧПУ: ноль у нижнего края листа, Y вверх — весь лист зеркалится вокруг своей высоты из «Бумага», и рисунок ложится у верхнего края настоящего листа) и «Реверс» (Y = −Y для станков с подачей листа назад: координаты становятся отрицательными, лист идёт вперёд). Дуги G2↔G3, I/J точные; предупреждение «выходит за лист» не срабатывает для намеренно отрицательного Y; предпросмотр показывает физическое положение на листе (позиция пера тоже); опция хранится в localStorage. Проверка G-кода пользователя: файл точно соответствует SVG (масштаб ровно 25.4/96, без зеркала, дуги ±0.0015 мм) — причина была именно в конвенции начала Y. Самотест: rust-ключ yorigin (bottom → Y297/287, reverse → Y−10) + оконная цепочка yo (селект → конверт → Y у верхнего края → возврат «Верхний край»).
- **0.5.17** — начертание и предпросмотр шрифта: под списком шрифтов появился выбор «Начертание» (Обычный / Жирный / Курсив / Жирный курсив) — для системных шрифтов это точный файл глифов из сканирования (у семейства показываются только реально установленные варианты), для Google-шрифтов вариант скачивается отдельным файлом и кешируется, а при отсутствии начертания у семейства (Google отвечает 400) — мягкий фолбэк на Regular с предупреждением; живая строка предпросмотра рисует реальные контуры глифов выбранного шрифта/начертания (те же outlines, что строит плоттер) — работает и для системных, и для Google-шрифтов; самотест: rust-проверки fstyle (Bold рисует иначе) и fontpreview (контуры возвращаются) + оконная цепочка sf расширена переключением начертания (bold_diff) и проверкой превью.
- **0.5.16** — выбор шрифта из системы: в выпадающем списке шрифта появилась вторая группа «Шрифты системы» — все семейства, найденные в стандартных каталогах (`~/.fonts`, `~/.local/share/fonts`, `/usr/local/share/fonts`, `/usr/share/fonts`, включая .otf и .ttc); имя берётся из таблицы name самого шрифта, файл читается с диска напрямую — без скачивания и интернета; кнопка «↻» пересканирует после установки новых шрифтов; самотест: rust-проверка списка и конвертации (sysfonts) + оконная цепочка «выбрать системный шрифт → Текст → G-code» (ui_sysfont).
- **0.5.15** — инверсия Y: галочка «Инвертировать Y» в карточке SVG для станков, у которых Y+ уходит вверх — печать больше не выходит вертикальным зеркалом; зеркало вокруг габаритов рисунка (след на листе не двигается), дуги G2↔G3, I/J пересчитываются; опции конвертации сохраняются в localStorage; самотест: rust-проверка зеркальной диагонали + оконная цепочка «SVG-файл → конверт → галочка → конверт» (ui_invy).
- **0.5.14** — в блоке «Готовый G-код» появилась строка «Открыть файл»: выбранный .gcode/.nc/.tap попадает и в поле, и сразу в панель G-код; строка «Файл G-code» из карточки SVG убрана (не дублировать); самотест вставляет синтетический файл через DataTransfer (file_applied/file_in_field).
- **0.5.13** — блок «Готовый G-код»: вставка из буфера и Ctrl+V прямо в поле, «Применить» отправляет программу в панель G-код (просмотр, правка, «Печатать»); самотест проверяет блок кликами в реальном окне (ui_paste).
- **0.5.12** — скорость «как в программе №1»: потоковое окно GRBL (character-counting) вместо «одна строка — один ok»; настоящие дуги G2/G3 в SVG; перелёты в серво-режиме — G1 на подаче рисования; пресеты пера без угла серво.
- **0.5.11** — кнопка «Стоп печать» (0x18); подача F один раз в начале файла; чип версии и «О программе».
- **0.5.10** — починена кнопка «$X — Разблокировать» (UI слал GET вместо POST; кнопка безопасности теперь переживает любой сбой транспорта).
- **0.5.9** — $X/$H идут в порт напрямую (send_now) даже при застрявшей очереди; список портов с автоопределением Arduino/CH340.
- **0.5.8** — загрузка готового G-кода; панель G-кода стала редактором (правка/вставка/сохранение).
- **0.5.7** — настоящий переключатель рабочих систем G54–G59 с синхронизацией `$G`.
- **0.5.6** — управление печатью перенесено в карточку подключения; исправлен байт F− (0x92), индикатор override.
- **0.5.5** — исправлена потеря событий статуса (индикатор подключения всегда показывал «Отключен»).
- **0.5.4** — исправлены однолинейные буквы «n/п/и» (контур замыкался в кольцо).
