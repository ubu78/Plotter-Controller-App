# Plotter Controller (Rust)

Десктопное приложение для управления перовым плоттером на базе **GRBL 1.1** (например, [Scalable-Pen-Plotter](https://github.com/ubu78/Scalable-Pen-Plotter)) по последовательному порту. Бэкенд на **Rust** (tao + wry/WebKitGTK, serialport), интерфейс React встроен в бинарник — приложение открывается в собственном окне, **без браузера, без HTTP-сервера и открытых портов**.

## Возможности

- 🔌 Подключение к GRBL через COM/USB-порт: статус (Idle/Run/Hold/Alarm), `$`-параметры с пресетом для плоттера, soft-reset, feed hold, крупные кнопки **$X** (разблокировка) и **$H** (homing), список портов с автоопределением Arduino/CH340
- ⚡ Быстрая отрисовка «как в программе №1»: потоковая передача G-кода окном (character-counting, окно 120 байт в 128-байтном RX-буфере платы) — планировщик GRBL видит 10–20 блоков вперёд, без торможения на стыках сегментов и без USB-round-trip на каждую строку
- 🖼 Импорт SVG → G-code с автомасштабированием под лист (**макс. формат — A4**) и настоящими дугами **G2/G3** (адаптивное разбиение кривых 0.02 мм + подгонка дуг); рисунок можно **перетащить мышкой прямо по листу** — смещение вшивается в G-код
- ✍️ **Текст / Markdown → G-code**: вставляете текст или .md — программа сама раскладывает строки и генерирует G-code; шрифты **Google Fonts** и **все шрифты, установленные в системе** (имя из самого файла, чтение с диска, без интернета) + **начертание** (Обычный/Жирный/Курсив/Жирный курсив) и живой предпросмотр реальными контурами; настройка размера и межстрочного интервала
- 🖋 Четыре стиля букв: «Ручка» (одна линия по штриху, без обводки контура) / «В одну линию» / «Залитые» / «Штриховка» (угол 0–180°)
- 📄 **Документ → G-code**: загрузка PDF / DOCX / TXT / MD — извлечение текста или однолинейная растеризация страницы в один клик
- 🪞 **Инвертировать Y**: если печать выходит зеркальной по вертикали (ось Y станка направлена вверх от точки старта — стандартное CNC-направление), включите галочку в карточке SVG — рисунок переворачивается на месте, габариты и положение на листе не меняются; дуги корректно меняют направление G2↔G3; настройка запоминается
- 🧭 **Начало Y станка**: три режима отсчёта Y относительно листа — «Верхний край» (Y = расстояние от верхнего края, как в предпросмотре — для протяжки листа вперёд), «Нижний край» (стандарт ЧПУ: ноль у нижнего края листа, Y вверх — рисунок ложится у верхнего края настоящего листа) и «Реверс» (Y = −Y для станков, у которых при Y+ лист уходит назад — координаты становятся отрицательными и лист подаётся в правильную сторону); высота листа берётся из «Бумага», дуги G2↔G3, предпросмотр показывает физическое положение на листе
- 🚀 **Скорость перемещений (travel speed)**: отдельная скорость холостых ходов с поднятым пером — переходы между элементами рисунка и возврат в ноль в конце. 0 — как раньше (серво — на скорости подачи, Z-режим — быстрый ход G0 платы); зададите число — все холостые XY-перемещения идут `G1` с этой скоростью в обоих режимах пера (вертикальные подъёмы Z остаются G0), независимо от $110/$111 платы. Поля в карточках SVG и Текст, действует на все конвертеры (SVG, текст/Markdown, PDF), хранится в localStorage
- 📐 **Поля листа по сторонам**: единое «Поле» стало четырьмя полями в мм — Лево / Право / Верх / Низ. Лево/верх сдвигают рисунок от краёв листа, право/низ ограничивают область печати: при «По центру» рисунок центрируется между полями, не влезающий — автоматически уменьшается с предупреждением. Действуют на SVG и PDF; у текста право/низ ограничивают раскладку строк, лево/верх задаётся «Старт X/Y». Старое значение мигрирует в четыре равных поля автоматически, область полей видна в предпросмотре пунктиром
- 🗺 Визуальный предпросмотр листа: траектория пера, **сетка 10 мм** (каждые 50 мм — жирнее), **рамка листа** по выбранному формату (A4/A5/Letter, альбомный — видна ещё до конвертации) и пунктирная рамка области полей; ручное управление (jog), рабочие системы координат **G54–G59**, нули осей, мм/дюйм
- 🖊 Перо: серво через выход шпинделя (`M3/M5`) или ось Z; пресеты одной кнопкой — «№1: ↑ M3 S30 · ↓ M5» (перо вниз **без угла, в положение покоя — на градус смотреть не нужно**) и «↑ M5 · ↓ M3 S45»; ползунок положения сервы и быстрый тест пера. Схема по умолчанию (0.5.19): перо вверх — `M3 S255`, перо вниз — `M5`
- ▶️ Управление печатью: Печатать / Пауза / Продолжить / **Стоп печать** (0x18), подача `F` один раз в начале файла, live-override **F− / F% / F+** с индикатором
- 📋 Блок «Готовый G-код»: **откройте файл** (.gcode/.ngc/.nc/.tap/.txt — вставляется сразу и в поле, и в панель G-код) или вставьте программу из буфера (Ctrl+V прямо в поле — надёжно в WebKitGTK), «Применить» — для текста из поля; редактор G-кода: правка, вставка, копирование, сохранение в файл
- 🛠 Настройки GRBL ($0–$132) с пресетом для плоттера
- 🌐 Локализация ru / en / et
- 🧪 Встроенный самотест: приложение проверяет себя в настоящем окне на мок-плате GRBL — без реального железа

## Быстрый старт (из исходников)

Требуется Rust ≥ 1.85 и Node.js ≥ 18. Системные пакеты (Debian/Ubuntu): `libwebkit2gtk-4.1-dev`, `libgtk-3-dev` (сборка) и `libwebkit2gtk-4.1-0` (запуск).

```bash
cd ui && npm install && npm run build && cd ..   # интерфейс -> ui/dist (встраивается при компиляции)
cargo build --release                            # окно без localhost
./target/release/plotter-controller
```

### Доступ к последовательному порту (Linux)

```bash
sudo usermod -aG dialout $USER   # затем перелогиниться
```

## Сборка AppImage (Linux x86_64)

```bash
bash appimage/build-appimage.sh
```

Скрипт собирает фронтенд, компилирует release-бинарник и упаковывает всё в один файл
`release/Plotter-Controller-<версия>-x86_64.AppImage`. Node.js в рантайме не нужен. Запуск:

```bash
./release/Plotter-Controller-0.5.23-x86_64.AppImage
# если FUSE недоступен:
./release/Plotter-Controller-0.5.23-x86_64.AppImage --appimage-extract-and-run
```

## Самотест (без реальной платы)

Приложение умеет проверять само себя в настоящем окне: конвертеры, сохранение файла, подключение, события.

```bash
python3 scripts/pty_mock.py &          # имитация платы GRBL на паре pty (печатает имя порта, напр. /dev/pts/5)
PLOTTER_SELFTEST=1 PLOTTER_SELFTEST_PORT=/dev/pts/5 ./target/release/plotter-controller
# на машине без экрана: xvfb-run ./target/release/plotter-controller
# печатает: SELFTEST {"status":true,"svg":true,...} и завершается
```

## Ограничения оборудования

- Максимальный размер бумаги — **A4** (210 × 297 мм); всё автоматически вписывается в область печати плоттера.
- Поднимаемая/опускаемая перьевая ось управляется через выход шпинделя `M3/M5` (серво SG90; при `$30=180` значение S — градусы 0–180) либо через ось Z — режим выбирается в «Настройках пера».
- Начало листа — левый верхний угол, X вправо, Y вниз (протяжка бумаги); ноль по кнопке «0» — `G10 L20 P1 X0 Y0`. Если станок считает Y иначе — селект «Начало Y» в карточке SVG («Нижний край» — стандарт ЧПУ, «Реверс» — лист подаётся назад при Y+). Стрелки jog говорят на языке станка: **↑ шлёт Y+** (и ↓ — Y−); куда на листе лежит «+» — определяет «Начало Y». Быстрая проверка: нажмите ↑ — если перо уходит к верхнему краю листа (или лист подаётся назад), ваш режим «Нижний край» или «Реверс»; если к нижнему — «Верхний край».

## История версий

Кратко, полная история — в git-логе и описаниях коммитов:

- **0.5.23** — герметичность оконного самотеста: проверка полей листа из 0.5.22 стала «мигать» в зависи­мости от того, что осталось в localStorage от прошлых запусков (сессия скриншотов вводила поля руками — Left 15 / Top 10 — и WebKitGTK хранит их в персистентном каталоге данных ~/.local/share/plotter-controller). Теперь инициализационный скрипт самотеста очищает `svgopts` до загрузки страницы — все цепочки (инверт-Y, начало Y, поля, drag) снова дают точные координаты независимо от истории. Код конвертации не менялся — сама программа 0.5.22 была корректна. 78 юнит-тестов зелёные, все оконные цепочки зелёные.
- **0.5.22** — travel speed + поля листа + сетка в предпросмотре. (1) **Скорость перемещений (travel speed)**: пользователь попросил отдельно задавать скорость холостых ходов при конвертации в G-code. С 0.5.12 перелёты в серво-режиме шли на скорости подачи рисования (чтобы не зависеть от $110/$111 платы) — теперь в карточках SVG и Текст появилось поле «Скорость перемещений» (мм/мин) для всех движений с поднятым пером: переходы между путями и возврат в ноль в конце. 0 — прежнее поведение (серво — на скорости подачи, Z-режим — быстрый ход G0 платы); зададите число — все холостые XY-перемещения идут командой G1 с этой скоростью в обоих режимах пера, число пишется прямо в строке перемещения, а скорость подачи восстанавливается командой `G1 F` сразу после опускания пера (F модальная — без восстановления весь путь рисовался бы на скорости перелёта); вертикальные подъёмы Z остаются G0. Опция хранится в localStorage и действует на все конвертеры (SVG, текст/Markdown, PDF). (2) **Поля листа по сторонам**: единое «Поле» стало четырьмя полями — Лево/Право/Верх/Низ (мм). Лево/верх сдвигают рисунок от краёв листа, право/низ ограничивают область печати: при «По центру» рисунок центрируется между полями, не влезающий — автоматически уменьшается с предупреждением; поля больше листа не ломают конвертацию (предупреждение «Margins leave no room on the sheet»). Область полей рисуется в предпросмотре оранжевым пунктиром. Действуют на SVG и PDF; у текста право/низ ограничивают раскладку строк, лево/верх задаётся «Старт X/Y». Старое значение из localStorage мигрирует в четыре равных поля автоматически; единый API-параметр `margin` сохранён для совместимости (действует, только когда все четыре per-side поля нулевые). (3) **Предпросмотр листа**: добавлена сетка 10 мм (каждые 50 мм — жирнее), рамка листа по выбранному формату (A4/A5/Letter с ограничением до A4 + альбомная ориентация) — видна ещё до первой конвертации — и пунктирная рамка области полей. Самотест: 4 rust-теста travel speed (отдельная скорость с восстановлением подачи, 0 = старый вывод без лишних строк, Z-режим переключает G0→G1 F, скорость = подаче — ноль лишних строк) + 5 rust-тестов полей (сдвиг лево/верх, центр между полями, право/низ в автомасштабе, legacy = четыре равных стороны, поля больше листа) + API-ключи travelfeed и margins в оконном селфтесте + новая UI-цепочка ui_margins (ввод 15 в «Лево» → `G1 X15.000`, обнуление → возврат к `X0.000`); 78 юнит-тестов зелёные.
- **0.5.21** — перетаскивание SVG-рисунка по листу починено: пользователь не мог передвинуть рисунок мышкой в предпросмотре. Причина — при подключённой плате позиция пера приходит несколько раз в секунду, и каждая перерисовка канваса стирала текущий сдвиг — рисунок визуально «возвращался» прямо во время перетаскивания, и лист казался неподвижным. Теперь незавершённый сдвиг живёт в ref: обновления позиции пера его сохраняют, а новая конвертация (в которую смещение уже вшито координатами) или смена «Начала Y» его сбрасывает; setPointerCapture обёрнут в try/catch (drag не падает на синтетических/неактивных указателях). В карточку SVG добавлена подсказка про перетаскивание (ru/en/et). Самотест: новая оконная цепочка dg — синтетический drag (down → пауза с live-обновлениями → move → up) должен увести первый G1 X ровно на 40px × мм/пиксель (проверено: X 0 → 26.5 при 0.662 мм/пиксель).
- **0.5.20** — стрелки Y в «Ручном управлении» перевёрнуты: пользователь заметил, что верхняя стрелка двигает не туда — на его станке «вверх» это Y+, а панель слала Y− (в коде было закомментировано «Y grows downward»). Теперь пад говорит на языке станка: ↑ = `Y+`, ↓ = `Y−` (X не менялся: → = X+). Сам G-код это не затронуло — его направление задаёт селект «Начало Y станка», а не джойстик; в подсказку к «Началу Y» (ru/en/et) добавлена быстрая проверка: нажмите ↑ — перо к верхнему краю листа (или лист назад) значит «Нижний край»/«Реверс», к нижнему — «Верхний край».
- **0.5.19** — M3 и M5 поменялись местами: серво на каретке физически развёрнуто, и правильной стала обратная схема — перо поднимает активный угол `M3 S<значение>`, опускает — положение покоя `M5` (штифт в нуле, без угла). Умолчания конвертеров и «Настроек пера» поменяны: «Перо вверх» = `M3 S255`, «Перо вниз» = `M5`; пресеты теперь «№1: ↑ M3 S30 · ↓ M5» и «↑ M5 · ↓ M3 S45». Сохранённые настройки пера не перезаписываются — конфигурация, уже подогнанная под развёрнутую серво (например, ↑ M3 S45 · ↓ M5), продолжает работать без изменений; Z-режим не менялся. Тесты и самотест теперь проверяют порядок (сначала подъём — потом опускание перед рисованием), тест-хелпер точности дуг переучен новой конвенции.
- **0.5.18** — начало Y станка: новая проблема — предпросмотр и SVG показывают рисунок у верхнего края листа, а при печати станок прокручивает лист и рисует не там; «Инвертировать Y» не помогает, потому что оно зеркалит рисунок вокруг его собственных габаритов (диапазон Y не меняется) и не может перенести рисунок на другой край листа. В карточке SVG появился селект «Начало Y»: «Верхний край» (как раньше — Y = расстояние от верхнего края, подача листа вперёд), «Нижний край» (стандарт ЧПУ: ноль у нижнего края листа, Y вверх — весь лист зеркалится вокруг своей высоты из «Бумага», и рисунок ложится у верхнего края настоящего листа) и «Реверс» (Y = −Y для станков с подачей листа назад: координаты становятся отрицательными, лист идёт вперёд). Дуги G2↔G3, I/J точные; предупреждение «выходит за лист» не срабатывает для намеренно отрицательного Y; предпросмотр показывает физическое положение на листе (позиция пера тоже); опция хранится в localStorage. Проверка G-кода пользователя: файл точно соответствует SVG (масштаб ровно 25.4/96, без зеркала, дуги ±0.0015 мм) — причина была именно в конвенции начала Y.
