# Plotter Controller 0.5.11 (desktop)

Управление перьевым плоттером [Scalable-Pen-Plotter](https://github.com/ubu78/Scalable-Pen-Plotter) через GRBL 1.1 (Arduino Uno). Десктопное приложение: открывается в собственном окне, **без браузера, без HTTP-сервера и открытых портов**. Бэкенд на Rust (tao + wry/WebKitGTK, serialport), интерфейс React/Vite встроен в бинарник (rust-embed), связь UI ↔ Rust — по IPC (схема `plotter://app/`).

## Сборка

Нужен Rust ≥ 1.85 (зависимости на edition 2024) и Node.js ≥ 18. Системные пакеты: `libwebkit2gtk-4.1-dev`, `libgtk-3-dev` (сборка), `libwebkit2gtk-4.1-0` (запуск, Debian/Ubuntu).

```sh
cd ui && npm install && npm run build && cd ..   # интерфейс -> ui/dist (встраивается при компиляции)
cargo build --release                            # окно без localhost
bash appimage/build-appimage.sh                  # release/Plotter-Controller-0.5.11-x86_64.AppImage
```

Пользователь должен быть в группе `dialout` (`sudo usermod -aG dialout $USER`, затем перелогин).

## Самотест (без реальной платы)

Приложение умеет проверять само себя в настоящем окне: конвертеры, сохранение файла, подключение, события.

```sh
python3 scripts/pty_mock.py &          # имитация платы GRBL на паре pty (печатает имя /dev/pts/N)
PLOTTER_SELFTEST=1 PLOTTER_SELFTEST_PORT=/dev/pts/N xvfb-run ./target/release/plotter-controller
# печатает: SELFTEST {"status":true,"svg":true,...} и завершается
```

## Структура

```
src/
  main.rs       окно (tao EventLoop<String> + wry/WebKitGTK), схема plotter://app/, IPC, самотест
  api.rs        единый диспетчер запросов UI: handle(grbl, method, path, body)
  grbl.rs       связь с GRBL: поток ok-подтверждений, опрос «?», шина событий Bus (без сокетов)
  gcode.rs      опции, бумага ≤ A4, эмиссия G-кода (ядро всех конвертеров)
  svg.rs        SVG → полилинии (svgtypes: дуги, H/V, S/T)
  text.rs       текст/Markdown → G-code, Google Fonts (кэш ~/.cache/plotter-controller/fonts), страницы
  skeleton.rs   однолинейные буквы: растр → Zhang–Suen → трассировка → RDP; и PDF-страницы
  doc.rs        DOCX (zip+roxmltree), TXT/MD (utf-8 / cp1251), PDF-текст (pdf-extract)
  pdf.rs        PDF-страница как рисунок: hayro → растр → однолинейные штрихи
ui/src/         React 18 + Vite: ConnectionPanel, ManualPanel, PenPanel, SourcePanel, Preview,
                GcodePanel, SettingsPanel, ConsolePanel; i18n ru/en/et; api.js — единственная точка транспорта
```

## Особенности

- Перо: серво SG90 через выход шпинделя — `M5` вверх, `M3 S255` вниз (настраивается в PenPanel, хранится в localStorage); режим оси Z тоже поддерживается; после команд пера — пауза `G4 P0.15`; в начале G-кода `$32=0`.
- Начало листа — левый верхний угол, X вправо, Y вниз (протяжка бумаги). Ноль по кнопке «0»: `G10 L20 P1 X0 Y0`. Бумага не больше A4 принудительно.
- PDF: страница рендерится как рисунок (hayro, 150 dpi) и утончается до однолинейных штрихов; «как текст» — через pdf-extract; векторного режима нет.
- «Сохранить .gcode» пишет файл через Rust (`~/Downloads` или домашняя папка) — в окне нет браузерных скачиваний.
- Языки интерфейса: русский, English, eesti (переключатель в шапке).
- Серво-позиция пера: в «Настройках пера» у команд с числом S появляются ползунок + числовое поле + выбор шага (1/5/10/15) — правят число S прямо в команде (M3 S255 → S = положение сервы; при $30=180 в GRBL S = градусы 0–180).
- Инфо-панель состояния подключения в карточке «Подключение»: цветной индикатор — «Подключен» (зелёный, рядом код состояния GRBL: Idle/Run/Hold/…), «Отключен» (серый), «Ошибка (Alarm)» (красный, пульсирующий, с подсказкой «Нажмите $X — разблокировать»); «Подключение…» и Door — жёлтые. Живой режим через aria-live для скринридеров.
- Быстрый тест сервы: под ползунком «перо вниз» — кнопки «▼ Перо вниз на N°» и «▲ Перо вверх»: отправляют текущую команду пера с числом S прямо из панели настроек; в подсказке кнопки видна точная отправляемая команда.
- Угол штриховки: ползунок 0–180° с шагом 1° плюс числовое поле для точного ввода любого угла.
- Кнопки $X / $H вынесены в крупный блок с подписями («Разблокировать» / «Парковка») и пояснением: $X снимает аварийную блокировку, $H запускает homing.
- Ручное управление: панель рабочих координат G54 — переключение мм/дюйм (`G21`/`G20`), строки осей X/Y/Z с рабочими координатами и кнопкой сброса в ноль (`G10 L20 P1 X0/Y0/Z0`), «Ноль XYZ» и «В ноль XYZ» (поднимает перо и уходит в `G0 X0 Y0`), джойстик X/Y и кнопки Z+/Z−.
- Скорость печати: «Подача» в панели SVG, «Скорость печати» в панели текста (одно поле) — попадает в `F` G-кода; во время печати скорость меняется в реальном времени кнопками `F−` / `F%` / `F+` (GRBL feed override ±10% / 100%).
- Кнопка «Стоп печать», подача один раз в начале файла, «О программе» (0.5.11): (1) в карточке «Подключение» рядом с «Печатать / Пауза / Продолжить» появилась красная кнопка «■ Стоп печать» — отправляет 0x18 (soft reset): плата перезагружается, очередь очищается, прогресс сбрасывается в ноль. Самотест прогоняет сквозной round-trip: короткая программа → прогресс 100% → «Стоп» → приветственный баннер платы → счётчики обнулены, статус Idle и связь на месте (stop:true), плюс DOM-проверка кнопки в реальном окне (ui_stop_btn:true). (2) Правило конвертации: скорость подачи записывается ОДИН раз в начале файла строкой «G1 F<подача>» (значение из настроек); линии рисуются без F — F у GRBL модальная и держится до изменения; дуги G2/G3 тоже без F. В режиме оси Z опускание пера сохраняет свою F<z_feed> (иначе погружение пошло бы на подаче рисования), сразу после него подача рисования восстанавливается строкой «G1 F»; в режиме серво (по умолчанию) F встречается в файле ровно один раз. Проверено юнит-тестами feed_is_written_once_at_the_top и z_mode_restores_drawing_feed_after_plunge. (3) В шапке после бейджа «🦀 Built in Rust» — чип версии («v0.5.11 ⓘ», значение берётся из Cargo.toml бэкенда по запросу version) и небольшое всплывающее окно «О программе»: что за приложение, как работает (без браузера и сети), что конвертирует, про печать/стоп/$X; три языка, закрытие крестиком.
- Снова починена кнопка «$X — Разблокировать» — причина была не там, где её искали в 0.5.9 (0.5.10): бэкенд-фикс send_now из 0.5.9 был верным, но до него из окна дело не доходило. В 0.5.9 кнопки $X/$H перевели с send('$X') на api('unlock'), а транспорт api(p, b) отправляет POST только когда передан второй аргумент: api('unlock') без body уходил как GET, диспетчер же понимал только («POST», «unlock») — заявка падала в «Unknown request: GET unlock», промис отклонялся, отклонение никто не ловил, и кнопка молча ничего не делала. Самотест 0.5.9 этого не заметил: он звал api::handle(&g, "POST", …) напрямую из Rust, минуя транспорт UI. Исправление в два независимых слоя: (1) UI теперь зовёт api('unlock', {}) / api('home', {}) и показывает ошибку в консоли, если она случится; (2) диспетчер принял unlock/home любым методом (_, "unlock") — сбой транспорта больше не может убить кнопку безопасности. Бонус: при клике $X/$H без подключения в консоли появляется «-- not connected: connect first --» вместо тишины. Самотест дополнен двумя независимыми проверками: прежний round-trip из Rust (мок-плата в Alarm → застрявшая строка → $X → Idle, unlock:true) и НОВАЯ UI-половина — самотест кликает настоящую кнопку $X в DOM и считает строки «> $X» в консоли до и после клика (ui_unlock_btn:{found,sent}). Негативный контроль: с воспроизведённым багом 0.5.9 (GET + только POST) тест даёт sent:false, то есть ловит именно тот отказ, на который жаловался пользователь.
- Исправление кнопки «$X — Разблокировать» и список портов с Arduino (0.5.9): (1) $X переставала работать после аварии: при ALARM настоящая GRBL не отвечает ok на строку, которая была «в полёте», флаг busy в бэкенде застревал навсегда, и $X вставала в очередь, которая никогда не двигалась. Теперь строка ALARM:… (и приветственный баннер «Grbl …» после сброса платы) очищает очередь и busy в приложении, а кнопки $X/$H отправляются через новый прямой путь send_now — минуя любые застрявшие строки, сразу в порт. В консоль пишется подсказка «press $X to unlock». Самотест проверяет сквозным round-trip: мок-плата уходит в Alarm (в точности как настоящая — без ok), приложение разблокируется, статус возвращается в Idle (unlock:true). (2) Список портов отсортирован: сначала Arduino (определяется по USB VID/PID: Arduino LLC 2341/…, Arduino.org 2A03/…, клоны на CH340 1A86:7523 и CH9102, а также по строкам производителя/продукта с «Arduino»), затем остальные USB-порты /dev/ttyUSB* и /dev/ttyACM*, затем системные (ttyS*, pts). Порт отображается с именем платы: «Arduino Uno · /dev/ttyUSB0», клоны подписаны «(CH340)», адаптеры — «CP210x»/«FTDI». Первый Arduino в списке выбирается автоматически при открытии и по кнопке ↻.
- Загрузка готового G-кода и редактор (0.5.8): в блоке «SVG → G-code» появилась строка «Файл G-code» — можно открыть готовый .gcode/.nc/.tap/.ngc/.txt без конвертации: файл попадает в панель «G-код» и сразу доступен «Печатать». Панель «G-код» из просмотра стала полноценным редактором: «Редактировать» (переключает просмотр/правку, правки сразу идут в печать), «Вставить» — G-код из буфера обмена (в режиме правки — в позицию курсора, иначе заменяет всю программу; если буфер недоступен — подсказка включить правку и нажать Ctrl+V), «Сохранить» — записывает текущий (в том числе отредактированный/загруженный) G-код в файл через Rust, «Копировать» — прежняя. Самотест проверяет редактор сквозным round-trip в DOM: клик «Edit» → ввод G21/G90/G0 X10 Y10/G1 X50 Y30 F3000/G1 X10 Y10/M5 через нативный value-сеттер → клик «Done» → предпросмотр содержит введённые строки (ui_gcheck: edit_btn/textarea/typed/pre_after = true).
- Рабочая система координат стала настоящим переключателем (0.5.7): плашка «G54» в «Ручном управлении» выглядела как кнопка, но была статичным текстом — клики ничего не делали. Теперь это выпадающий список G54–G59: выбор отправляет G54/G55/… плате, а все кнопки «ноль» (⟲ на осях, «0» в джойстике, «Ноль XYZ») записывают смещение в активную систему (G10 L20 P1…P6). При подключении приложение запрашивает `$G` и синхронизирует селектор с фактическим состоянием платы (ответ `[GC:…]` парсится в бэкенде и идёт в статус). Самотест проверяет round-trip: G55 → плата → статус G55.
- Управление печатью в карточке «Подключение» (0.5.6): кнопки «Печатать», «Пауза», «Продолжить» (оранжевая) и F− / F% / F+ перенесены из панели SVG в блок подключения, рядом с индикатором прогресса. Кнопки неактивны без подключения (для «Печатать» — ещё и без сконвертированного G-кода).
- Исправление F− (0.5.6): F− отправляла байт 0x88, который GRBL 1.1 игнорирует (правильный realtime-байт −10% — 0x92), поэтому скорость не менялась. F+ / F% были корректны, но без индикатора эффект был не виден. Теперь плата отчитывается полем Ov из статуса — рядом с кнопками виден текущий override («F 120%»). Сквозная проверка в самотесте: два F+ → плата отвечает Ov:120.
- Исправление статуса (0.5.5): индикатор подключения всегда показывал «Отключен», хотя порт был открыт. Причина: события статуса/лога/настроек от бэкенда приходят в окно в «сыром» виде ({"type":"status",…}), а диспетчер в api.js понимал только сообщения с полем t ('rpc'/'ev') — события молча отбрасывались, UI оставался в начальном состоянии. Теперь диспетчер передаёт сырые события подписчикам, плюс статус запрашивается один раз при загрузке страницы (страховка от пропущенного события). Самотест теперь проверяет фактическое состояние баннера в DOM: ui_banner = {cls:"connstat ok", txt:"ConnectedIdle"} на мок-плате.
- Исправление букв (0.5.4): в режиме «Ручка» строчные «n/п/и» и похожие рисовались замкнутым квадратом — скелет буквы распадался на ножку и арку, а сшивка штрихов проводила перо по базовой линии, замыкая контур в кольцо. Теперь: короткие шипы-артефакты утоншения срезаются (despine), а штрихи сшиваются только через крошечный зазор (≤ 0.1 размера шрифта) — большие зазоры становятся перелётом с поднятым пером. Проверено регрессионными тестами и рендером G-кода.
- Стили букв (панель «Текст») — выбор кнопками с мини-предпросмотром стиля (буква «О» в каждом режиме), по умолчанию — «Ручка»:
  - **Ручка (от руки)** — одна непрерывная линия по центру каждого штриха, без обводки контура; штрихи буквы сшиваются в один путь по ближайшим концам (как письмо от руки). Скорость ×1.0.
  - **В одну линию** — те же однолинейные штрихи, но каждый с отдельным опусканием пера. Быстрый контур, тонкие буквы. Скорость ×1.5.
  - **Залитые** — контур буквы + плотная сплошная заливка горизонтальными зигзаг-линиями (шаг ≈ размер/15) — буквы как печатные, но медленно. Скорость ×0.5. Шаг заливки настраивается в мм (0 = авто): меньше — плотнее и медленнее, больше — реже и быстрее.
  - **Штриховка** — контур + заливка диагоналями (шаг ≈ размер/4). Средняя скорость. Скорость ×0.8. Угол штриховки настраивается ползунком и числовым полем 0–180° (по умолчанию 45°), шаг — как у «Залитых».
